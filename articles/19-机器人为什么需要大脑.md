机器人为什么需要"大脑"

—— 一台机械臂要绕开盒子画个圆，五件事为什么不能塞进一个循环（1.1）


一、先说这台机器人要干的活

桌面上放一个半径 4.5 厘米的盒子。二连杆机械臂，大臂 30 厘米、小臂 25 厘米，末端要沿半径 11 厘米的圆走一圈，路过盒子的时候往外绕开。

就这一件事。把它拆开，是五步：

| 环节 | 在这台机器人上具体是什么 | 多久做一次 |
|---|---|---|
| 感知 | 关节编码器读数，换算成末端坐标 | 10 ms |
| 决策 | 走圆；离盒子近了就往外推 | 跟规划一起 |
| 规划 | 算出未来 200 ms 的 21 个关节角 | 50 ms |
| 控制 | 插值出"此刻"该在的关节角，限幅、限位 | 1 ms |
| 执行 | 电机带着关节走过去 | 跟着控制走 |

"大脑"就是上面三步——感知、决策、规划。"小脑"是下面两步。

为什么必须这么分，先看大脑的代码。


二、大脑的代码，一共二十行

决策和规划合在一起，就是 `brain/brain.c` 里这个函数。它只回答一个问题：**t 时刻，末端应该在哪**。

    static void plan_path(const struct plan_ctx *c, uint64_t t_ns,
                          float *px, float *py)
    {
        float t = (float)(t_ns - c->t_start) / 1e9f;
        float ang = c->omega * t;
        float x = c->cx + c->radius * cosf(ang);
        float y = c->cy + c->radius * sinf(ang);
        float dx = x - c->ox, dy = y - c->oy;
        float d = sqrtf(dx * dx + dy * dy);
        float margin = c->orad + 0.06f;   /* 留 6 cm 安全边 */

        /* 离障碍物太近，沿径向推开。越近推得越狠，但最多推 8 cm。 */
        if (d < margin && d > 1e-4f) {
            float push = (margin - d) / margin;
            push = push > 1.0f ? 1.0f : push;
            x += dx / d * push * 0.08f;
            y += dy / d * push * 0.08f;
        }
        *px = x;
        *py = y;
    }

前三行是那个圆：圆心 (0.32, 0.06)，半径 0.11 米，角速度 1.1 弧度每秒，所以一圈大约 5.7 秒。

中间三行算出这个点离盒子中心多远，`margin` 是盒子半径加 6 厘米安全边。

`if` 那一段就是"决策"：离得太近，沿着"从盒子指向这个点"的方向往外推。推的距离是渐变的——贴着边走时推满 8 厘米，离得远时一点都不推。所以绕出来的不是个直角，是平滑地鼓出去一块。

这不是查表，是每一拍当场算出来的。

算完这个点，`ik()` 把它变成两个关节角。21 个点连着算，就是未来 200 毫秒的关节轨迹。

这就是大脑干的全部事情。它不碰电机。


三、大脑交出去的是一张时间表，不是电流

大脑算完，把 21 个点打包成这个结构体交给小脑：

    struct rb_traj_seg {
        uint64_t t0_ns;
        uint64_t t_gen_ns;   /* 大脑做完决策的时刻，用来算端到端延迟 */
        uint32_t n;
        uint32_t seq;
        struct rb_traj_point p[RB_TRAJ_POINTS];
    };

`t0_ns` 是这条轨迹"从什么时候开始生效"。大脑算完立刻发，`t0` 定在"现在加 60 毫秒"，这 60 毫秒是留给传输和调度的余量。

小脑收到以后，按**自己的钟**，每毫秒在这 21 个点之间插值。它不问大脑"现在该到多少"，它只看表。

这一条是整套架构的地基：**大脑说的是"从这一刻起按这条线走"，不是"现在动"**。


四、现在把五件事塞回一个循环

不分进程，每一拍按顺序做完：算未来 200 毫秒的 21 个点 → 取第一个点当指令 → 伺服更新。

    t_now = (float)(t0 - t_start) / 1e9f;

    /* 1. 规划：未来 200 ms 的 21 个路点，全算一遍 */
    for (int k = 0; k < TRAJ_POINTS; k++) {
        float xk, yk, a, b;

        plan_path(t_now + (float)k * TRAJ_DT, &xk, &yk);
        if (ik(xk, yk, &a, &b) < 0) {
            a = q1;
            b = q2;
        }
        if (k == 0) {
            nq1 = a;
            nq2 = b;
            g_sink = a + b;
        }
    }
    busy_us(think_us);

    /* 2. 取第一个点当这一拍的指令 */
    q1_cmd = nq1;
    q2_cmd = nq2;

    /* 3. 伺服：一阶滞后，时间常数 20 ms */
    dt = (float)period / 1e9f;
    q1 += (q1_cmd - q1) * dt / tau;
    q2 += (q2_cmd - q2) * dt / tau;

注意这一版**没有缓冲**：想要新指令，就得现在算完。

`busy_us(think_us)` 是"算法变贵"的替身。今天的势场法算 21 个点只要 2 微秒，所以这个参数默认是 0；调成 2000 代表换成视觉检测，调成 20000 代表换成模型推理。

三组都跑同一台机械臂、同一条圆、同一个盒子：

| 规划耗时 | 实际周期 | 电机指令更新 | 稳态跟随误差 | 末端离盒子最近 |
|---|---|---|---|---|
| 0 | 991.0 µs | 1009 Hz | 0.035 rad | 89.2 mm |
| 2 ms | 2016.1 µs | 496 Hz | 0.061 rad | 88.4 mm |
| 20 ms | 20030.5 µs | 50 Hz | 0.324 rad | 68.3 mm |

第一列到第二列只差一句话：**周期 = 规划耗时 + 1 毫秒**。四件事是串行的，规划没算完，电机就收不到新指令。

第三列是后果。电机指令更新从 1009 Hz 掉到 496 Hz，再掉到 50 Hz。50 Hz 是什么概念——一个画圆的动作，每秒只给你 50 个点，电机是一顿一顿转的。

第四列更难看：跟随误差从 0.035 涨到 0.324 rad，九倍。第五列跟着遭殃：末端离盒子最近的距离从 89 毫米缩到 68 毫米，盒子半径 45 毫米，只剩 23 毫米余量。

第一行要单独看：**什么都不干的时候，这个循环是好的**。1 kHz，误差 0.035 rad，圆也画得对。所以问题不是"循环写错了"。


五、真正要命的不是这一次变慢

表里那个 2 毫秒、20 毫秒是我加上去的。真实的机器人不会原地踏步：今天是势场法，明天加视觉检测，后天换成模型。算法只会越来越贵。

而这个循环的结构决定了：**算法有多贵，控制就有多粗**。两者被同一个节拍绑死。

想升级算法？可以，但要同时重写控制器——因为它们在同一个循环里，共用一个周期。

这不是性能问题，是结构问题。所以答案不是"把循环优化一下"，是把它拆开。


六、拆开之后

同一个机器人，同样的虚拟机，大脑的推理耗时从 0 加到 80 毫秒：

| 大脑推理 | 小脑周期 | 跟随误差 |
|---|---|---|
| 0 | 1.025 ms | 0.0570 rad |
| 10 ms | 1.216 ms | 0.0570 rad |
| 40 ms | 1.045 ms | 0.0570 rad |
| 80 ms | 1.086 ms | 0.0570 rad |

80 毫秒是什么概念：规划周期才 50 毫秒，大脑已经算不完了。小脑还是 1.0 ~ 1.2 毫秒一拍。

第二列在这台虚拟机上波动不小（10 ms 那组反而最差），因为宿主机会挂起空闲的 vCPU，这不是大脑造成的。但第三列四组一模一样：**0.0570，一个数字都没动**。

再把大脑直接 `kill -9`：

    [cereb] 状态切换 0 -> 1 @ 453 ms
    [cereb] 状态切换 1 -> 2 @ 3603 ms
    [cereb] 状态切换 2 -> 3 @ 4152 ms

1 是开始跟轨迹，2 是失联后保持，3 是安全停机。轨迹缓冲从 206 毫秒掉到 103、再掉到 9，跟随误差还是 0.0570。

大脑慢、大脑死，机器人都不抖。这就是分开的意义。


七、所以"大脑"到底是什么

它不是"算得更多的那块 CPU"。

它是一层**允许慢、允许错、允许死**的东西。它慢的时候下面那层不受影响，它死的时候下面那层自己停下来。

它交出去的东西只有两样：**一条轨迹，一个时间**。不是电流，也不是"现在动"。

有了这条边界，"更聪明的算法"和"更稳的控制"才能各自进步，互不牵制。
