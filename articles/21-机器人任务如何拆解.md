机器人任务如何拆解

—— 前进、转弯、避障、停车：四个动作怎么变成四段能自己判对错的代码（1.3）


一、这一篇换一台机器人

前两台都是二连杆臂，只能原地动。这一篇的四个动作——前进、转弯、避障、停车——是底盘的动作，所以换成一台差速底盘：两个轮子，指令只有两个数，线速度 v 和角速度 w。上限 0.3 m/s、1.5 rad/s，加速度上限 0.6 m/s²，控制周期 20 毫秒（50 Hz）。

场景：从 (0, 0) 出发，去 (1.00, 0.55)。中间 (0.80, 0.10) 有根半径 10 厘米的柱子，正好卡在路上。

就这一件事。要拆的就是它。


二、"拆"到底拆的是什么

不是把一个大函数切成四个小函数。切成小函数，它们还是得按固定顺序调用，改一个照样崩另一个。

拆解是给每个动作定三件事：**它自己判断什么时候算干完**、**它自己记住干到哪了**、**它把结果告诉外面，只有三种**。

三件事写成一个结构体：

    struct task {
        const char *name;
        int  (*tick)(struct task *t, struct world *w);
        void (*reset)(struct task *t);
        void *st;
    };

每 20 毫秒 tick 一次，返回 `TASK_RUNNING`、`TASK_SUCCESS`、`TASK_FAILURE` 之一。

四个动作对上去，就是四行：

| 动作 | 什么时候算干完 | 它自己记什么 |
|---|---|---|
| 前进 | 离目标点不到 12 毫米 | 目标点、当前是"先转"还是"再走" |
| 转弯 | 角度差小于 0.46 度，而且真的停了 | 目标角 |
| 避障 | 后退、转、前进、转回来，四步走完 | 走到第几步、从哪起步、往哪边绕 |
| 停车 | 速度真的到 0 | 什么都不用记 |

注意第一列写的都是"世界到了某个状态"，没有一条是"我执行了多少步"。


三、前进那个任务

四个里最长的就是它，三十行：

    static int goto_tick(struct task *t, struct world *w)
    {
        struct goto_st *s = t->st;
        float dx = s->tx - w->x;
        float dy = s->ty - w->y;
        float d = sqrtf(dx * dx + dy * dy);
        float err;

        if (d < 0.012f) {              /* 离目标不到 12 毫米就算到 */
            w->v_cmd = 0.0f;
            w->w_cmd = 0.0f;
            return TASK_SUCCESS;
        }

        err = wrap_pi(atan2f(dy, dx) - w->th);

        if (s->phase == G_TURN) {      /* 先原地对准，再走 */
            w->v_cmd = 0.0f;
            w->w_cmd = clampf(6.0f * err, -w->wmax, w->wmax);
            if (fabsf(err) < 0.05f)
                s->phase = G_DRIVE;
            return TASK_RUNNING;
        }

        if (fabsf(err) > 0.6f) {       /* 偏太多，停下重新对准 */
            s->phase = G_TURN;
            return TASK_RUNNING;
        }

        w->w_cmd = clampf(4.0f * err, -w->wmax, w->wmax);
        w->v_cmd = fminf(w->vmax, 1.2f * d);   /* 快到点就减速 */
        return TASK_RUNNING;
    }

三处值得看。

开头算的是 `s->tx - w->x`，**目标点减当前位置**。不是"还剩多少米没走"。

这是整篇文章的分水岭。如果进度写成 `odom += fabsf(v) * dt`，它就挂在"轮子转了多少圈"上——中途被避障打断，绕行那几秒的轮子转动照样记进里程，任务会以为自己走完了。第六节量这件事的代价。

`if (fabsf(err) > 0.6f)` 是"走到一半发现偏了，回去重新对准"。没有这一句，任务只会闷头往前开，越偏越远。

最后 `1.2f * d`：离得远就按上限走，离得近就按比例减速。到点门限 12 毫米，就是这么落下来的。


四、两个组合器

只有两个。行为树里那些 Sequence、Fallback、Parallel 的名字，剥掉术语，干的就是排队和插队。

顺序：一拍只推进一个子任务。

    static int seq_tick(struct task *t, struct world *w)
    {
        struct seq_st *s = t->st;
        int r;

        if (s->i >= s->n)
            return TASK_SUCCESS;

        r = task_tick(s->kid[s->i], w);

        if (r == TASK_SUCCESS) {
            task_reset(s->kid[s->i]);
            s->i++;
            if (s->i >= s->n)
                return TASK_SUCCESS;
            return TASK_RUNNING;      /* 下一个任务，下一拍才开始 */
        }
        return r;
    }

`s->i++` 之后 `return TASK_RUNNING`——子任务干完了，这一拍**不接着跑下一个**。代价是任务之间固定隔 20 毫秒；好处是每一拍干了什么，日志里一行不差。

抢占：高优先级任务还在跑，低优先级这一拍完全不 tick。

    static int arb_tick(struct task *t, struct world *w)
    {
        struct arb_st *s = t->st;
        int r = task_tick(s->hi, w);

        if (r == TASK_RUNNING)
            return TASK_RUNNING;      /* 高优先级占着，低的这一拍不动 */
        if (r == TASK_FAILURE) {
            task_reset(s->hi);
            return TASK_RUNNING;      /* 避障失败也不许撞，下一拍再试 */
        }
        return task_tick(s->lo, w);
    }

低优先级是被**冻结**，不是被**重置**。避障结束以后，前进接着从它自己记住的目标点往下走，没有人需要告诉它"你刚才走到哪了"。

整棵树就这么搭出来：

    kids[0] = task_goto(0.45f, 0.00f);
    kids[1] = task_goto(1.00f, 0.00f);
    kids[2] = task_goto(1.00f, 0.55f);
    kids[3] = task_stop();

    root = arb(task_avoid(), seq_n(kids, 4));


五、跑一遍

    [  0.02 s] 前进→(0.45,0.00) 位置 ( 0.00,  0.00)
    [  3.48 s] 前进→(1.00,0.00) 位置 ( 0.44,  0.00)
    [  4.08 s] 避障             位置 ( 0.55,  0.00)
    [ 10.40 s] 前进→(1.00,0.00) 位置 ( 0.67, -0.53)
    [ 15.24 s] 前进→(1.00,0.55) 位置 ( 0.99, -0.01)
    [ 19.52 s] 停车             位置 ( 1.00,  0.54)

    任务完成，用了 19.52 秒（976 拍）
    停在 (1.000, 0.538)，朝向 89.6 度
    离目标还剩 11.8 mm

第二行到第三行：前进才走了 0.6 秒，避障就插进来了，位置停在 (0.55, 0)。之后 6.3 秒全是避障在跑。

第四行是关键。避障交还控制权的时候，机器人在 (0.67, -0.53)——被推偏了 53 厘米。前进任务重新 tick，它算的是"我离 (1.00, 0.00) 还有多远"，于是自己拐回去。

没有人写"拐回去"这段代码。它就是那句话的结果。


六、不拆会怎样

同一台底盘，同一个起点，同一个目标，同一根柱子。任务写成增量：前进 0.45 米 → 前进 0.55 米 → 左转 90 度 → 前进 0.55 米 → 停。避障写成循环里的一个 `if`。

    [  0.02 s] 前进 0.45 m  位置 ( 0.00,  0.00)  里程 0.00 m
    [  3.10 s] 前进 0.55 m  位置 ( 0.45,  0.00)  里程 0.00 m
    [  3.56 s] 避障（写在循环里） 位置 ( 0.54,  0.00)  里程 0.09 m
    [  9.88 s] 前进 0.55 m  位置 ( 0.67, -0.53)  里程 1.00 m
    [  9.90 s] 左转 90 度  位置 ( 0.67, -0.53)  里程 1.00 m
    [ 11.34 s] 前进 0.55 m  位置 ( 0.67, -0.53)  里程 0.00 m
    [ 12.90 s] 避障（写在循环里） 位置 ( 0.68, -0.15)  里程 0.38 m
    [ 18.76 s] 前进 0.55 m  位置 ( 0.16, -0.00)  里程 1.22 m

    结束，用了 18.80 秒（940 拍）
    停在 (0.158, -0.003)，朝向 89.6 度
    离目标还剩 1007.4 mm

看第四行。避障结束的位置和拆解版**一模一样**：(0.67, -0.53)。但里程已经是 1.00 米——第二段的额度只有 0.55 米，绕行那 0.70 米全被记进去了。于是它当场判定"第二段走完了"，在 x = 0.67 就转 90 度，而不是在 x = 1.00 转。

后面每一步都从错的地方开始。12.90 秒又撞上一次避障——因为在 x = 0.67 就转弯，正好从柱子边上擦过去——最后停在 (0.16, -0.00)。

| | 拆解版 | 不拆版 |
|---|---|---|
| 避障结束时位置 | (0.67, -0.53) | (0.67, -0.53) |
| 第二个路点误差 | 12 mm | 624 mm |
| 避障次数 | 1 次 | 2 次 |
| 最终离目标 | 11.8 mm | 1007.4 mm |
| 用时 | 19.52 s | 18.80 s |

**同一个避障动作，两边被推偏的距离一模一样。** 差的是之后那一拍：拆解版问"我离目标还有多远"，不拆版问"我的额度用完了吗"。

一米的差距不是一次错出来的，是第一个任务停错 62 厘米，后面三个任务从错的地方开始，越错越远。


七、拆开以后才能单独测

揉在一个循环里的版本做不了这件事——你没法只要"转弯"、不要"前进"。拆开之后每个任务都是一个函数，喂一个假世界进去就能跑一千遍，随机起点、随机目标、随机障碍。

    == 转弯：1000 组随机起始朝向、随机目标角 ==
      最终角度误差 p50 0.35 度  最大 0.40 度
      用时 p50 74 拍  p99 125 拍
      800 拍内没转完：0 组；中途转过头：0 次

    == 前进：1000 组随机起点、随机目标点（无障碍）==
      终点误差 p50 11.81 mm  最大 11.94 mm
      用时 p50 297 拍  p99 457 拍
      1500 拍内没到：0 组

    == 避障：1000 组随机障碍（表面距离 5~17 cm）==
      绕完用时 p50 261 拍  p99 261 拍  最大 261 拍
      800 拍内没绕完：0 组；撞上：0 组

三组各有各的意思。

转弯**中途转过头 0 次**：角速度是 `6 × 角度差`，差多少转多少，是收敛的，不会冲过目标再倒回来。

前进那一列的终点误差贴着 12 毫米，因为任务就是拿 12 毫米判定"到了"的。**它不是精度，是门限。** 有意义的数是"1000 组全部到点"。

避障的用时 p50、p99、最大全是 261 拍。因为绕行是定长动作：后退 0.15 米、转 60 度、前进 0.55 米、再转回来，每一步都受 0.3 m/s 和 1.5 rad/s 的上限约束。**5.2 秒是固定的**，调度上要按这个留余量。

不过第六节那次占了 6.3 秒，比 5.2 秒长。差别在于起点：单测是从静止开始，实跑是带着 0.3 m/s 冲进去的，光把速度换到 −0.12 就要 0.7 秒。**任务时长要按"最坏的进入条件"算，不是按单测的 p50。**


八、拆开要花多少钱

    == 走完一遍顺序（含一次 task_reset）==
      挂 1 个                     7.8 ns
      挂 2 个                    14.2 ns
      挂 4 个                    26.6 ns
      挂 8 个                    45.3 ns
      ── 每多挂一个任务          5.4 ns

    == 整棵树 ==
      一个真实叶子（前进）      15.0 ns
      整棵树（抢占+顺序4+避障）  22.8 ns
      占 20 ms 周期            0.0001%

组合器的单价是 5.4 纳秒——往顺序里多挂一个任务，多花的钱就是这个数，比一次 `sinf` 便宜。

整棵树 tick 一次 22.8 纳秒。50 Hz 一拍 20 毫秒，**这一拍里能 tick 八十七万次**。拆解在时间上根本不是成本。

真正花时间的是任务自己：一个"前进" tick 一次 15 纳秒，因为里面有一次 `atan2f`、一次 `sqrtf`。钱花在算几何，不花在拆。


九、所以"任务拆解"是什么

它不是分文件，也不是画一张漂亮的框图。

它是把每个动作写成一句**能自己判断真假的话**：

- 前进：离目标不到 12 毫米了吗？
- 转弯：角度差小于 0.46 度了吗？
- 避障：四步绕行走完了吗？
- 停车：速度真的到 0 了吗？

这四句话都能在没有机器人的时候验证——第七节那一千组就是这么来的。

写不成这种话的动作，就不是一个任务，只是一段代码。**"再走 0.8 米"写不成一句话，因为"再"要靠上下文才成立；"到 (1.00, 0.00)"可以。**

第六节那一米的差距，就是从这儿来的。
