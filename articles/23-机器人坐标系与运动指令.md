机器人坐标系与运动指令

—— 位姿三个数、两个坐标系、一条带有效期的指令（1.5）


一、这一篇翻译一句话

还是那台差速底盘。上层只会说一句话："去 (1.00, 0.55)。"底盘只认两个数：线速度 v、角速度 w。

中间要翻译四道：

    世界系目标 (1.00, 0.55)
        ↓ 减掉车头朝向，折进 ±π
    车体系方位 err
        ↓ 比例控制 + 限幅
    车体系速度 (v, w)
        ↓ 打包，带时间戳和有效期
    一条 motion_cmd

每一道都能搞错。这一篇把五个最常见的错各跑一遍，看差多少。

起点：车在 (0.00, 0.00)，车头朝 +120.0°。目标 (1.00, 0.55)，直线距离 1.141 米。


二、位姿是三个数，不是两个

    struct pose {
        float x, y;     /* 米，世界系 */
        float th;       /* 弧度，世界系，从 +x 轴逆时针 */
    };

`(x, y)` 只说了车在哪儿，`th` 说的是车头朝哪儿。

少了 `th`，同一个坐标，"往前"就是无穷多个方向。后面所有的"前方 1 米有障碍"、"往前走 0.3 米"、"左转 90 度"，全部失去意义。

所以凡是涉及位置的地方，都得三个数一起给：地图给你目标点，要连朝向一起给（很多任务不只是"到那儿"，还要"从那个方向到那儿"）；你给底盘指令，要连当前朝向一起用；传感器报一个点在哪儿，也是在某个坐标系里的三个数。


三、同一个点，两种说法

目标点 `(1.00, 0.55)`，在世界系里离 +x 轴 28.81°。车头朝 120°。

同一个点，换到车体系看：

    世界系坐标   (+1.00, +0.55)   离 +x 轴 +28.81°
    车体系坐标   (-0.02, -1.14)   离车头 -91.19°
    距离         1.141 m

世界系说"右前方 29 度"，车体系说"正右方 91 度"。差 120.0 度，正好是车头朝向。

**这个点在车的正右方。** 世界系那两个数看着像"右前方"，是因为 +x 轴不是车头。

换轴就是转一次：

    struct vec2 pose_to_body(const struct pose *p, struct vec2 w)
    {
        float c = cosf(p->th);
        float s = sinf(p->th);
        struct vec2 b;

        b.x = c * w.x + s * w.y;
        b.y = -s * w.x + c * w.y;
        return b;
    }

矩阵里只有 cos 和 sin。所谓"坐标系变换"，在代码里就是六行。

反着转回去是 `body_to_world`，把 `s` 的符号翻一下。两个函数连大括号加起来十八行，整个 1.5 的坐标系部分就这些。


四、世界系速度，底盘做不出来

上层要的是"正东 0.30 m/s"。换到车体系：

    世界系速度   (+0.300, +0.000)
    车体系分解   (-0.150, -0.260)
    → 后退 0.150，向右 0.260

差速底盘两个轮子，能做的只有两件事：沿车头走、绕车心转。车体系分解出来的 x 和 y，只有一个能用——y 是横向，它做不出来。

横向那 0.260 要么丢掉，要么先转过去再走。

硬把 0.30 m/s 当"前进"（把横向丢了）：走 1 秒，方向错 120.0°，终点偏 52.0 cm。

所以"线速度"这个词在机器人里是含糊的。世界系的线速度有两个分量；车体系的线速度只有一个——沿车头，另一个自由度叫角速度。

**说"线速度"必须说清是哪个系。** 这一句也解释了为什么底盘的指令只有 (v, w)，不是 (vx, vy)：不是接口偷懒，是机械上就只有这两个自由度。


五、忘了减 θ

`bearing_to` 里那句 `- p->th`，是整篇最容易漏的一个符号。漏了会怎样：

    /* 正确 */
    float err = bearing_to(p, tx, ty);              /* 减了 θ，也折进 ±π */

    /* 错误 */
    float err = atan2f(ty - p->y, tx - p->x);       /* 忘了 - p->th */

同一个控制器，只改这一行，跑 20 秒：

| | 终点 | 离目标 | 走的路 | 用时 |
|---|---|---|---|---|
| 正确 | (+0.99, +0.55) | 12.0 mm | 1.27 m | 5.97 s |
| 不减 θ | (−0.11, −0.29) | 1391.0 mm | 6.00 m | 20.00 s |

1391 毫米。车 20 秒走了 6.00 米，最后停在离起点 0.31 米的地方——一直在原地附近打转。

为什么？因为 `err` 变成了世界系方位 28.81°，跟车头没关系了。车看到"目标在左前方 29 度"，于是左转；转完再算，还是 28.81°（还是没减 θ），继续左转。它永远觉得目标在左前方，于是永远左转，边走边转，画着圈。

`v` 一直没归零，因为它算出来的距离始终在一米上下。

一个符号，把"到点"变成"绕圈"。


六、角度是周期量

`bearing_to` 里还有一句 `wrap_pi`：

    float wrap_pi(float a)
    {
        while (a > PI_F)
            a -= 2.0f * PI_F;
        while (a <= -PI_F)
            a += 2.0f * PI_F;
        return a;
    }

`atan2` 给的是 (−π, π]，减完 `th` 之后可能落到 (−2π, 2π)。不折回去，同一个 20 度的误差会变成 340 度：

| | 初始误差 | 转过 | 用时 |
|---|---|---|---|
| 折进 ±π | +20.0° | +13.1° | 0.267 s |
| 不折 | −340.0° | −333.1° | 3.991 s |

14.9 倍。

注意两行的**物理结果一样**——车最后都对准了，因为转 340 度和转 −20 度是同一个朝向。所以这个 bug 不会让车走错，只会让车白转一圈半、多花 3.7 秒。

这 3.7 秒里车是原地打转。对一台 0.3 m/s 的巡检车，3.7 秒是 1.1 米的行程。如果这期间有东西在靠近，就不是"慢一点"的问题了。

（用 `while` 不用 `fmod`：`fmod` 对负数向零取整，−3π 折出来是 −π，不在一半的区间里。±π 附近会咬人。）


七、从位姿到 (v, w)

有了方位角，控制器只有十几行：

    static void nav_ok(const struct pose *p, float tx, float ty,
                       float *v, float *w)
    {
        float err = bearing_to(p, tx, ty);
        float d = hypotf(tx - p->x, ty - p->y);

        if (d < TOL) {
            *v = 0.0f;
            *w = 0.0f;
            return;
        }
        *v = fminf(VMAX, 1.2f * d);
        *w = clampf_(4.0f * err, -WMAX, WMAX);
    }

两个系数值得说一句。

`1.2` 的单位是 1/s：还剩 0.25 米时降到 0.3 m/s，正好是上限。再远就全速，再近就减速。这不是调出来的，是"还剩多远就该多慢"直接写出来的。

`4` 的单位也是 1/s：误差 0.25 弧度时转 1.0 rad/s，到 0.375 弧度就顶到上限 1.5。误差越小转得越慢，接近 0 时 `w` 也接近 0，不会来回摆。

两个都是"每秒消掉多少误差"。这是比例控制的全部含义，不需要 PID 那一套。


八、一条指令不止两个数

底盘只要 `v` 和 `w`。但从上层传到下层的这条指令，得装五个数：

    struct motion_cmd {
        uint32_t seq;       /* 序号，丢掉乱序到达的旧指令 */
        uint32_t ttl_ms;    /* 多久之内有效 */
        uint64_t t_ns;      /* 什么时候算出来的 */
        float v, w;         /* 车体系速度 */
    };

`seq` 防的是"后发先至"：两条指令在路上交叉了，先发的后到。没有序号，车会先执行新的、再执行旧的，轨迹拧成一个结。

`ttl_ms` 防的是"过期执行"。为什么车体系的指令会过期？因为它说的是"沿**当前**车头方向走"——车头一直在转，这句话的意思一直在变。世界系目标没有这个问题，"去 (1.00, 0.55)" 放一小时还是那句话。

接收端三行：

    int cmd_accept(const struct motion_cmd *c, uint64_t now_ns, uint32_t last_seq)
    {
        if (c->seq <= last_seq)
            return 0;       /* 旧指令，乱序到了 */
        if (now_ns < c->t_ns)
            return 0;       /* 时间倒退，两边的钟不是一个 */
        if ((now_ns - c->t_ns) / 1000000ull > (uint64_t)c->ttl_ms)
            return 0;       /* 过期 */
        return 1;
    }

顺序不能换：先看序号，再看时间，最后才限幅。反过来先限幅，等于把一条本该扔掉的指令改小再执行。


九、过期就扔，超限就等比缩

车以 1.0 rad/s 左转，队列里躺着一条 `(v=0.30, w=0.00)`，说的是"沿当时车头走 0.30 米"。晚取出来多久，就偏多少：

| 晚了 | 车头已转 | 终点偏 | ttl=100 ms |
|---|---|---|---|
| 100 ms | 5.7° | 3.0 cm | 收 |
| 200 ms | 11.5° | 6.0 cm | 扔 |
| 400 ms | 22.9° | 11.9 cm | 扔 |
| 800 ms | 45.8° | 23.4 cm | 扔 |

走的是同样 0.30 米，方向错了。400 毫秒就是 11.9 厘米——比那根柱子的半径（10 厘米）还大一点。

第二件事是限幅。上层要 `v=0.50, w=2.00`（转弯半径 0.250 米），底盘上限 0.30 / 1.50。两种截法：

    float k = 1.0f;

    if (fabsf(c->v) > vmax)
        k = fminf(k, vmax / fabsf(c->v));
    if (fabsf(c->w) > wmax)
        k = fminf(k, wmax / fabsf(c->w));

    c->v *= k;
    c->w *= k;

| | v | w | 转弯半径 | 1 秒后 | 朝向 |
|---|---|---|---|---|---|
| 分别截断 | 0.300 | 1.500 | 0.200 | (+0.200, +0.186) | +85.9° |
| 等比缩放 | 0.300 | 1.200 | 0.250 | (+0.233, +0.159) | +68.8° |

两点相距 4.3 cm，朝向差 17.2°。

分别截断看起来更"直接"——v 归 v 的限、w 归 w 的限，各管各的。但它改的是轨迹形状：转弯半径从 0.250 压到 0.200，拐得更急。想让它慢一点，结果它拐了个更小的弯。

**限幅的对象不是两个数，是一条轨迹。** 要保轨迹，就得等比缩。


十、回到标题

一条运动指令，前后是四样东西：

**一个位姿。** 三个数，(x, y, θ)。少一个，"往前"就没定义。

**两个坐标系。** 世界系说目标，车体系说动作。同一个点，一边是"右前方 29 度"，一边是"正右方 91 度"，差的就是 θ。变换是六行代码，漏一个 `- th` 就是 1391 毫米。

**一个周期量。** 角度折进 ±π。不折不会走错终点，但会白转一圈半、多花 3.7 秒。

**一条带时限的指令。** `seq` 防乱序，`ttl` 防过期，限幅要等比。车体系的速度指令保鲜期只有几十毫秒——这是它和世界系目标的根本区别。

还有一条藏在"线速度"这个词里：世界系的线速度是两个分量，车体系的线速度只有一个。差速底盘的第二个自由度是角速度，不是横向。所以横向那 0.26 m/s，从一开始就不该出现在指令里。

整条链路 30.1 纳秒，占 20 毫秒周期的 0.00015%。慢的不是算，是这四样东西里任何一样写错之后，你要花多久才能发现。
