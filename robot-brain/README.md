# robot-brain — 机器人大小脑

Linux 当大脑做推理规划，小脑做 1 kHz 实时控制，两者通过共享内存协作。

小脑的核心约束只有一条：**大脑可以卡、可以死，机器人不能倒。**

```
        大脑（20 Hz）                    小脑（1 kHz）
   ┌──────────────────┐          ┌──────────────────────┐
   │ 感知：读状态帧     │          │ 收轨迹片段            │
   │ 决策：势场避障     │  轨迹    │ Hermite 插值          │
   │ 规划：逆解 200ms   │ ───────► │ 变化率限幅            │
   │ 下发：带时间戳     │  共享内存 │ 关节限位 → 伺服模型   │
   └──────────────────┘          └──────────────────────┘
            ▲                              │
            └──────── 状态帧 ◄──────────────┘
```

## 快速开始

```bash
make
bash test/run-demo.sh 5      # 演示：跑起来，然后拔掉大脑
bash test/run-jitter.sh 6    # 四组周期抖动对照
bash test/run-degrade.sh     # 大脑变慢 / 猝死
bash test/run-latency.sh 6   # 推理耗时对动作的影响
```

需要 root（`SCHED_FIFO` 和 `mlockall` 要权限）。

## 已经验证过的

在 openEuler 24.03 SP4 / 内核 6.12.0 / 4 vCPU（VMware）上实测：

- 大脑规划、小脑执行，末端沿圆走并绕开障碍物
- 大脑被 `kill -9` 后，小脑 250 ms 进保持、800 ms 进安全停机，跟随误差不变（0.057 rad）
- 推理耗时 80 ms（超过 50 ms 规划周期）时，轨迹缓冲从 198 ms 掉到 50 ms，但动作仍然连续
- 绑核 + FIFO + 独占核把丢拍率从 14.4% 降到 7.1%

## 没有验证过的

**Jailhouse 的 ivshmem 后端（`transport/transport_ivshmem.c`）没有跑过。**

Jailhouse 要求 CPU 暴露 `vmx`/`svm` 并由它独占物理核与内存映射，当前开发用的 VMware 虚拟机两者都没有。同一台机器上也试过 Bao，它根本没有 x86 版本。

这段代码是按 Jailhouse 的 ivshmem 约定写的，上裸机后需要现场调试。详见 `jailhouse/README.md` 和 `docs/architecture.md` 第一节。

**这不影响架构本身的验证**：协议层、时间语义、降级逻辑都已经在载体 A 上测过，换载体只替换传输后端。

## 两个载体

```bash
# 载体 A：Linux 共享内存 + futex（已实测，虚拟机可跑）
bin/cerebellum --transport shm:/robot-brain --hz 1000 --rt 50 --cpu 1
bin/brain      --transport shm:/robot-brain --hz 20

# 载体 B：Jailhouse ivshmem（需要裸机）
bin/cerebellum --transport ivshmem:/sys/bus/pci/devices/0000:00:0f.0 --hz 1000
```

上层代码完全一样，`include/shm_proto.h` 一行不用改。

## 参数

**大脑**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--hz` | 20 | 规划频率 |
| `--think-us` | 0 | 模拟推理耗时（忙等微秒），用来测降级 |
| `--lead-ms` | 60 | 轨迹提前量，留给传输和调度 |
| `--duration-s` | 0 | 跑多久，0 表示一直跑 |

**小脑**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--hz` | 1000 | 控制频率 |
| `--tau-ms` | 20 | 伺服时间常数（一阶滞后模型） |
| `--rt` | 0 | SCHED_FIFO 优先级，0 表示不用 |
| `--cpu` | -1 | 绑到哪个核，-1 表示不绑 |
| `--wd-hold-ms` | 250 | 多久没轨迹进保持 |
| `--wd-safe-ms` | 800 | 多久没轨迹进安全停机 |

## 数据怎么看

小脑退出时打一份汇总，几个量要分清：

- **周期** —— 两次唤醒之间的间隔，1 kHz 的目标是 1000000 ns
- **单拍耗时** —— 循环体本身跑了多久，必须远小于一个周期
- **丢拍** —— 周期超过 1.5 倍的次数
- **计划年龄** —— 大脑决策到动作执行完的时间。这个数天然接近「提前量 + 前瞻窗口」（60 + 200 ms），它是设计参数，不是延迟
- **缓冲余量** —— 队列里还有多少毫秒的轨迹可走。降到 0 就该进保持了

前两个量容易混。早期版本只量了单拍耗时，看着"平均 1.3 微秒很漂亮"，其实那根本不是周期——真周期是 1.1 毫秒。

## 环境限制

这台开发机的宿主是 i5-7300HQ，4 核，虚拟机拿走了全部 4 个 vCPU。宿主会挂起空闲的 vCPU，所以周期最大值能到几十毫秒。**在这个平台上，1 kHz 控制环的周期数据只能看相对趋势，绝对值没有意义。** 要拿真实数据得上裸机或专用板卡。
